# Analisis de casos: Scrum y DevOps

## Introduccion

En clase se reviso Scrum como marco de trabajo agil y se relaciono con la cultura DevOps. Scrum ayuda a organizar el trabajo en ciclos cortos, a recibir retroalimentacion constante y a entregar valor de forma incremental. Eso lo hace una buena opcion para proyectos donde hay cambios frecuentes, riesgos tecnicos y necesidad de validar resultados rapidamente.

En ambos casos que se analizan a continuacion, Scrum encaja bien porque permite dividir el trabajo en partes pequeñas, revisar avances con frecuencia y mejorar el proceso en cada iteracion. Al mismo tiempo, Scrum apoya a DevOps porque favorece la colaboracion, la automatizacion, la integracion continua y la mejora constante.

## 1. Desarrollo de un sistema de analisis de datos para una institucion educativa

### Marco de trabajo elegido: Scrum

Para este caso elegiria Scrum porque una universidad no necesita solo construir un sistema de una sola vez, sino ir ajustandolo segun lo que vaya descubriendo en el uso real. Un sistema de analisis de datos puede comenzar con algunos indicadores basicos y luego crecer con nuevas necesidades, como seguimiento de notas, asistencia, desercion, rendimiento por curso, alertas tempranas o reportes para directivos. Y va evolucionando a medida que se disponibilizan los datos para el consumo.

Scrum es apropiado porque permite trabajar por sprints cortos y entregar avances utiles en cada ciclo. El Product Owner puede priorizar primero lo que mas valor aporta a la institucion, por ejemplo los datos mas importantes para la toma de decisiones de la Dirección academica. El equipo de desarrollo puede construir el sistema por etapas: captura de datos, limpieza, tableros, analitica y alertas.

### Como Scrum apoya a DevOps

Scrum apoya de forma positiva a DevOps porque crea un flujo de trabajo ordenado entre planeacion, desarrollo, prueba y mejora. Esto encaja con la idea de DevOps de entregar rapido, aprender pronto y corregir sin esperar demasiado.

- En la **planificacion del sprint**, el equipo define metas claras y tareas pequenas. Esto ayuda a organizar mejor la automatizacion y las pruebas.
- En el **daily scrum**, se detectan bloqueos rapidamente. Eso evita que los problemas se acumulen y frenen la entrega continua.
- En la **revision del sprint**, los usuarios pueden ver avances reales y decir si el sistema realmente les sirve.
- En la **retrospectiva**, el equipo identifica que funciono y que se debe mejorar. Esa mejora continua es parte clave de DevOps.

Este caso se beneficia mucho de practicas DevOps como:

- **Integracion continua**, para probar cambios frecuentes sin esperar al final del proyecto.
- **Pruebas automatizadas**, para verificar que los calculos, reportes y tableros funcionen bien.
- **Infraestructura como codigo**, para crear ambientes de desarrollo y prueba de forma repetible.
- **Monitoreo**, para revisar el uso del sistema, el rendimiento de los reportes y posibles errores en produccion.

### Conclusión del caso

Scrum es una buena eleccion porque permite construir el sistema paso a paso, validar resultados con usuarios reales y ajustar el producto segun la retroalimentacion. DevOps complementa este enfoque al facilitar la automatizacion, la calidad tecnica y la entrega continua. En una institucion educativa, esta combinacion ayuda a que el sistema de analisis de datos sea util, flexible y realmente orientado a mejorar el aprendizaje.

## 2. Migracion de datos y sistemas a la nube en una empresa de logistica

### Marco de trabajo elegido: Scrum

Para este caso tambien elegiria Scrum porque la migracion a la nube es un proyecto complejo y con riesgos. No se trata solo de mover servidores o bases de datos, sino de revisar aplicaciones heredadas, dependencias, seguridad, rendimiento, costos y continuidad del servicio. Por eso conviene dividir el trabajo en partes pequenas y controladas.

Scrum permite hacerlo de manera ordenada. El Product Owner puede priorizar primero los sistemas mas criticos para la operacion logistica. El equipo puede avanzar por incrementos como diagnostico, pruebas en nube, automatizacion, migracion parcial y validacion final. Asi se reduce el riesgo de afectar la operacion de la empresa.

### Como Scrum apoya a DevOps

En una migracion a la nube, DevOps necesita coordinacion estrecha entre desarrollo, operaciones y seguridad. Scrum ayuda porque organiza ese trabajo en ciclos cortos, visibles y medibles.

- En la **planificacion del sprint**, se definen tareas concretas como mover una base de datos, preparar un entorno en la nube o automatizar un despliegue.
- En el **daily scrum**, se detectan riesgos rapidamente, por ejemplo errores de compatibilidad, problemas de permisos o retrasos en pruebas.
- En la **revision del sprint**, se verifica si el sistema migro correctamente, si responde mejor y si ya permite escalar con mayor facilidad.
- En la **retrospectiva**, el equipo ajusta su forma de trabajo y mejora la coordinacion entre desarrollo, operaciones y seguridad.

Este caso se conecta muy bien con practicas DevOps como:

- **Automatizacion de despliegues**, para reducir tareas manuales y errores humanos.
- **Infraestructura como codigo**, para crear entornos consistentes y repetibles en la nube.
- **Pruebas automaticas**, para confirmar que la migracion no rompa aplicaciones ni bases de datos.
- **Monitoreo y observabilidad**, para revisar disponibilidad, rendimiento y uso de recursos despues de la migracion.

### Conclusión del caso

Scrum ayuda a controlar la migracion por entregas pequenas y verificables. DevOps aporta automatizacion, pruebas, monitoreo y una mejor colaboracion entre areas. En una empresa de logistica, esta combinacion es muy valiosa porque permite migrar con menos riesgo, mantener la continuidad del negocio y ganar eficiencia y escalabilidad.

## Conclusión general

Scrum es una metodologia apropiada para ambos casos porque permite trabajar de forma iterativa, priorizar lo mas importante y obtener retroalimentacion temprana. Su relacion con DevOps es positiva porque Scrum organiza el trabajo y DevOps ayuda a que ese trabajo se entregue con mas rapidez, calidad y estabilidad.

En el caso del sistema de analisis de datos, Scrum ayuda a construir una solucion que realmente apoye la mejora del aprendizaje. En el caso de la migracion a la nube, Scrum ayuda a reducir riesgos y a avanzar de forma segura. En los dos casos, la combinacion con DevOps fortalece la colaboracion, la automatizacion y la mejora continua.
